# work-push

풀 → 커밋 → 푸시를 순서대로 수행한다. 각 단계가 실패하면 다음 단계로 넘어가지 않고 사용자에게 상황을 보고한다.

## 절차

### 1. 현재 상태 확인
- `git status`, `git diff --stat`으로 변경 파일을 확인한다.
- 현재 브랜치가 무엇인지 확인한다. (기본 브랜치는 `main`)

### 2. 풀 (먼저 한 번만)
- `git pull`을 **한 번** 실행한다.
- 로컬 변경 때문에 pull이 거부되면 `git pull --autostash`로 다시 시도한다.
- 충돌이 나면 **여기서 멈추고** 충돌 파일을 사용자에게 보고한다. 임의로 해결하거나 커밋/푸시로 넘어가지 않는다.

### 3. 커밋
- 변경 파일을 **파일 단위로** 스테이징한다. `git add -A`, `git add .`는 쓰지 않는다.
- 아래 파일은 기본적으로 커밋하지 않는다. 사용자가 포함하라고 한 경우만 포함한다.
  - `*.pb.cc`, `*.pb.h` (빌드 때 자동 생성되는 파일)
  - `Binaries/`, `Intermediate/` 등 빌드 산출물
  - 이번 작업과 무관해 보이는 변경 (애매하면 사용자에게 묻는다)
- 커밋 메시지는 아래 형식을 따른다.

#### 커밋 메시지 형식

```
[YYYY-MM-DD] 제목
1. 변경내용
- 세부내용
2. 변경내용2
- 세부내용
- 세부내용2
...
```

- 날짜는 오늘 날짜(`date +%F`)를 `YYYY-MM-DD`로 쓴다.
- 제목은 이번 작업 전체를 한 줄로 요약한다.
- 변경내용은 번호를 붙여 큰 단위로 나누고, 각 번호 밑에 `- ` 로 시작하는 세부내용을 적는다.
- 한국어로 쓴다.
- 메시지 맨 끝에는 시스템이 안내하는 Co-Authored-By 줄이 있으면 그대로 붙인다.
- 여러 줄이라서 메시지를 임시 파일에 UTF-8로 저장하고 `git commit -F <파일>`로 커밋한다. (`-m`으로 넘기면 한글/줄바꿈이 깨질 수 있다.)

### 4. 푸시
- `git push`를 실행한다. 업스트림이 없으면 `git push -u origin <현재 브랜치>`를 쓴다.
- `--force`, `--force-with-lease`는 **절대 쓰지 않는다.** 푸시가 거부되면 이유를 보고하고 멈춘다.

### 5. 결과 보고
- 커밋 해시와 제목, 포함한 파일, 푸시한 브랜치를 짧게 알려 준다.
- 제외한 파일이 있으면 무엇을 왜 뺐는지도 함께 알려 준다.

## 주의
- 커밋/푸시는 사용자가 이 스킬을 부르거나 명시적으로 요청했을 때만 한다.
- `--no-verify` 등으로 훅을 건너뛰지 않는다. 훅이 실패하면 원인을 보고한다.
- 이미 푸시된 커밋을 `--amend`로 고치지 않는다.
